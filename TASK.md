## Task 1 — tail-explain-summary (code)

At the very end of every `--explain` run of `verify-policy` (normal mode only —
hook mode stays byte-silent, and ALL non-`--explain` output stays byte-identical;
many tests pin it), print a final "summary — what just happened:" section AFTER the
decision recap. Lines, each stating its provenance layer using the same machinery
`--state-explain` uses ([cli]/[env]/[config]/[auto]/[default]):

- `terraform state on disk : <path> [layer]` — or "none configured" plainly.
- `promises in force       : N enforcing, M not — from <requirements source>` plus
  a parenthesized id list capped the way the decision block caps lists (first few
  + "+K more"); "none loaded" when no requirements are configured.
- `provider                : <schema source/provider name>` when a provider schema
  is in force (name the captured provider and resource-type count), else
  "no schema configured — resource shapes not checked".
- `proposed change         : <proposal file> — <one-line census>` (document kind
  and, for terraform kinds, block count by resource type from the same census the
  extractors already compute; never invent a census the run did not perform).
- `result                  : APPROVED/DENIED (exit N)` restating the decision LAST
  (the terminal's final line remains the decision — an existing ordering
  requirement), followed when DENIED by "it violated these promises:" with the
  refuted promise ids, and/or "blocked by N built-in findings: [kinds]" when
  built-ins fired; an APPROVED with unchecked coverage keeps its qualifier
  ("APPROVED — N unchecked"). The section never claims a promise violation for a
  built-in finding or vice versa.

Wording: plain prose; do not use the words "honest/honestly/quietly/simply" in the
new output strings (task 5 sweeps documentation; do not create new occurrences in
product output). Tests: a focused test module pinning the section's presence,
ordering (after the recap), provenance labels, both result shapes, the
no-requirements and no-schema lines, hook-mode absence, and non-explain
byte-identity. README: update every quoted `--explain` tail in the scenario
sections to the real new output (rerun the quoted commands; keep the
solver-minted-witness '(…)' masking convention).
