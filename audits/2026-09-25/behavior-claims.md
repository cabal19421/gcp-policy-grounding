# Audit: live probes of every documented behavioural guarantee

Read-only audit of `gcp-policy-grounding` at `main` 90248ba (probed on branch
`agent/audit-behavior-claims`, whose tree is identical to 90248ba for every
audited path). **Nothing was fixed.** The only file this task wrote inside the
repository is this report.

## Scope

Every documented *behavioural* guarantee — the sentences in `README.md`,
`sec_requirements/README.md`, `gcp-ground --help` / every subcommand's `--help`,
and the module docstrings that make a promise about what a run does — checked by
running the tool and reading what came out. Claims about *names existing* are the
sibling `docs-vs-code` / `phantom-code` tasks' scope; a name is touched here only
where a run prints it at a user.

The families probed, all of them from the task's minimum list:

hook byte-silence and exit-2 findings · non-`--explain` byte identity · the
freshness ceiling on both paths in all three spellings · a refused config vs
tfstate auto-detection · the clock resolved once · the five provider-schema
outcomes · the solver census · TTY-only colour · summary-last ordering ·
`deny_rules` exception subtraction and `has_principal_exceptions` · the
allow×deny shadow arcs · the effective org-policy fold · the four
compile-requirements rejections and `--check` drift · the evidence floor. Six
further documented guarantees were probed opportunistically (`--format json`'s
`sec` gate, `--precedence`, `--drift-policy`, `--completeness`,
`--no-auto-baseline`, `scan-command`), and one of them produced this report's
most serious finding.

## Method

* **Every input is FRESH.** No repository fixture and no `examples/` file is an
  input to any probe. The corpus is a made-up two-project organisation
  ("zolt.example", `organizations/770` → `folders/771` → `projects/zolt-prod`,
  `projects/zolt-lab`) with its own snapshot, sidecar, tfstate, provider schema,
  IAM / deny / org-policy documents, `terraform show -json` plans, hook events
  and requirement corpora — authored by four generator scripts under the task's
  scratchpad (`probes/mkcorpus.py`, `mkdocs.py`, `mkplans.py`, `mkwake.py`) plus
  three scratch repository trees for config discovery. Repository fixtures were
  *read* to learn record shapes; none was ever passed to the tool. One reference
  run against `examples/terraform/main.tf.json` is marked as such below and was
  used only to confirm the probe harness itself worked.
* **Exit codes are captured directly from the process,** never through a pipe:
  every probe runs `python -m gcp_grounding …` through `subprocess.run` with
  `capture_output=True` and records `proc.returncode` (`probes/drive.py`). The
  child's environment is scrubbed of every `GCP_GROUNDING_*` variable before each
  run, so no probe inherits a stray setting.
* **TTY claims use a real pty** on both stdout and stderr (`drive._run_pty`), so
  `isatty()` is genuinely true rather than simulated.
* Interpreter: `/home/jones/Downloads/gcp-policy-grounding/.venv/bin/python`
  (CPython 3.14.7), `PYTHONPATH` pinned to this worktree, cwd the worktree root.
  z3 present (every report header reads `[z3]`).
* The snapshot is stamped `captured_at: 2026-09-20T00:00:00Z`; probes pin the
  clock with `--as-of 2026-09-21T00:00:00Z` (fresh) or `2026-10-05T00:00:00Z`
  (15 days stale) so nothing depends on the wall clock.

Probe scripts, for anyone re-running: `p_fresh.py` (freshness, identity, colour,
summary), `p_census.py` (census, schema), `p_compile.py` / `p_compile2.py`
(compile rejections, drift, collections, floor), `p_shadow.py` / `p_wake.py`
(allow×deny), `p_fold.py` (org fold), `p_config.py` / `p_final.py` (discovery,
clock), `p_edge.py` (durations, terraform routing, abstain notes, bash policy,
fail-open), `p_extra.py` / `p_drift*.py` (the extra guarantees).
